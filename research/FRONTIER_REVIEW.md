# CMP memory frontier review

Research date: 2026-09-12. Scope: selected primary papers and author reports, principally 2024–2026. This is a bounded mechanism/evaluation review, not an exhaustive leaderboard. Dates below identify first publication/submission unless stated otherwise. Mechanisms are confirmed as described in the cited sources; performance figures are author-reported, not independently reproduced here.

The supplied CMP result—32/40 for both CMP and task-filtered BM25, with both missing all eight unanchored paraphrases—establishes no retrieval-quality advantage over that baseline. Durable journals, generation fencing, source-linked facts, and retention are useful engineering properties; they do not establish semantic recall or a new memory algorithm. The next experiment should isolate semantic access and evidence validity before increasing architectural complexity.

## Nine primary sources and what they establish

| Source and date | Confirmed mechanism / evidence | Critical interpretation for CMP |
|---|---|---|
| [Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory](https://arxiv.org/html/2504.19413v1), 2025-04-28 | An LLM extracts candidate facts using recent turns and a conversation summary. Semantic nearest neighbors inform ADD/UPDATE/DELETE/NOOP decisions. Its graph variant adds entities and relations. LoCoMo comparisons report quality, latency, and token savings. | Extraction, consolidation, vector retrieval, and graph facts are established prior art. Baseline RAG explores chunk sizes but only top-1/top-2 retrieval; that is not an exhaustive modern retrieval baseline. Lower query latency does not by itself establish lower lifetime cost after memory construction. The graph variant is not uniformly better: the paper reports no multi-hop gain over base Mem0. |
| [MemGPT: Towards LLMs as Operating Systems](https://arxiv.org/abs/2310.08560), 2023-10-12; foundational antecedent | The model uses function calls and control-flow interrupts to move information between immediate context and external memory tiers. | Agent-controlled context management predates the review period. A durable external store alone is a weaker capability than deciding what to retain, when to retrieve, and when evidence is sufficient. |
| [Benchmarking AI Agent Memory: Is a Filesystem All You Need?](https://www.letta.com/blog/benchmarking-ai-agent-memory/), 2025-08-12 | Letta reports 74.0% LoCoMo accuracy with GPT-4o-mini and file tools. Files are embedded for semantic search; the agent must search first and can issue repeated searches before answering. | This is an author/vendor experiment, not independent adjudication. The filesystem result is **not a lexical-only baseline**: embeddings, query reformulation, and an iterative agent loop contribute. It motivates a controlled agentic-search baseline with equal tool-call and token budgets, not a conclusion that storage structure is irrelevant. |
| [Zep: A Temporal Knowledge Graph Architecture for Agent Memory](https://arxiv.org/html/2501.13956v1), 2025-01-20 | Graphiti links raw episodes to extracted entities/facts; distinguishes event-valid time from ingestion time; invalidates conflicting edges while preserving history. Retrieval combines dense search, BM25, graph traversal, and reranking. Zep reports 71.2% versus 60.2% full-context accuracy on LongMemEval with GPT-4o. | The 18.5% headline is a relative improvement, approximately 11 percentage points. Results compare a complete pipeline with full context, so they do not isolate the causal contribution of graphs. The paper explicitly says episode/source traversal was not examined in its experiments. Provenance links and bitemporal representation therefore have architectural precedent, while their effect on auditable correctness still needs direct evaluation. |
| [A-Mem: Agentic Memory for LLM Agents](https://arxiv.org/html/2502.12110v1), 2025-02-17; later NeurIPS 2025 version | Notes include original content, timestamps, generated keywords, tags, contextual descriptions, embeddings, and links. Similarity retrieval proposes neighbors; an LLM creates connections and updates earlier notes' semantic attributes. | Beyond lexical retrieval, the concrete contribution is write-time contextualization and evolving associations. In the inspected v1, final retrieval is top-k dense similarity over enriched notes; “network” does not automatically imply multi-hop traversal at read time. Derived descriptions can drift; test fidelity to source evidence separately from answer accuracy. Attractive embedding plots do not establish semantic correctness. |
| [LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory](https://arxiv.org/html/2410.10813v1), 2024-10-14 | Five abilities: extraction, cross-session reasoning, temporal reasoning, updates, and abstention; 500 questions, with simulated and human-edited user-assistant histories. Experiments support finer-grained turns, fact-expanded index keys, time-aware query expansion, and structured reading. | These simple designs are required baselines before claiming novelty. Fact-only compression can lose useful context. Retrieval and reading are distinct failure points: correct evidence retrieval does not guarantee a correct answer. Synthetic histories and terminal question answering do not establish robust stateful task execution, recovery, or deletion behavior. |
| [Evaluating Very Long-Term Conversational Memory of LLM Agents](https://arxiv.org/abs/2402.17753), 2024-02-27 | LoCoMo uses persona/event-graph-grounded machine-generated conversations, checked and edited by humans; evaluates QA, event summarization, and multimodal dialogue. | It provides repeatable long-history evaluation, but conversational recall is narrower than durable agent memory. Comparisons must pin the released data, question categories, and scoring protocol; headline dataset statistics and downstream subsets differ. QA alone does not test whether an agent correctly persists an action result, survives interruption, or respects a later revocation. |
| [MemOS: A Memory OS for AI System](https://arxiv.org/abs/2507.03724), 2025-07-04 | Proposes unified management of plaintext, activation-based, and parameter memories. MemCubes carry content plus provenance/version metadata and support composition, migration, and evolution. | Provenance, versioning, lifecycle control, and an OS analogy are already explicit research themes. Treat the broad unification proposal as architecture, not proof that all memory types are practical or beneficial for a Go/SQLite application. Do not confuse this paper with separately named MemoryOS systems. |
| [Locomo-Plus: Beyond-Factual Cognitive Memory Evaluation Framework for LLM Agents](https://arxiv.org/abs/2602.10715), 2026-02-11 | Targets latent user constraints whose later triggers are semantically disconnected from the original cues. Proposes constraint-consistency evaluation instead of relying on string matching and explicit task-type prompts. | This directly challenges any claim that unanchored or implicit memory use is an untouched research problem. It is relevant to CMP's failure slice, although applying a latent constraint is harder than retrieving an ordinary paraphrased fact. Transfer to CMP remains an untested hypothesis; no scores from this paper were reproduced. |

## Three promising, falsifiable research directions

1. **Source-preserving semantic access with measured error propagation.** Keep original journal spans immutable; add separate, versioned semantic keys and embeddings rather than replacing evidence. Compare task-filtered BM25, dense retrieval, hybrid retrieval, fact-expanded keys, and a bounded iterative-search agent under equal retrieved-token and tool-call budgets. Measure evidence recall, source precision, final answer quality, and abstention separately. Hypothesis: enrichment or reformulation closes the unanchored-paraphrase gap without importing neighboring-task facts. Reject the hypothesis if improvement disappears on held-out paraphrase families or adds unacceptable false matches. Embeddings themselves would be an implementation improvement, not research novelty; the interesting result is an experimentally established fidelity/recall trade-off under evidence constraints.

2. **Evidence validity across updates, delayed writes, and revocation.** Couple CMP's generation fencing and journals to fact validity intervals and explicit supersession dependencies. Construct sequences with late-arriving older statements, conflicting sources, corrections, deleted evidence, interrupted extraction, and replay. Ask both “what is true now?” and “what was supported then?” Compare against latest-write-wins and a temporal retrieval baseline. Hypothesis: source-linked validity and replay semantics prevent stale or unsupported answers at similar retrieval cost. Report stale-answer rate, historical-answer accuracy, citation validity, replay consistency, and revoked-fact exposure. The research opportunity is the measured interaction between storage correctness and model memory behavior; temporal graphs and provenance alone are established mechanisms.

3. **Memory-trigger generalization under distractors.** Extend the synthetic pilot with independently authored tasks where a remembered constraint should change an action without appearing in the request. Add matched controls where the same memory is irrelevant, expired, contradicted, or belongs to another task. Split by scenario/template family rather than random question. Compare full context, hybrid retrieval, iterative search, and CMP using an identical reader/model. Hypothesis: an explicit constraint-trigger representation improves appropriate activation without excessive irrelevant activation. Measure constraint-consistent task outcomes, false activation, negative transfer, and resource cost. LoCoMo-Plus provides a close precedent; CMP should contribute stronger task-grounded provenance/revocation tests or a mechanism with a controlled advantage, not relabel its benchmark idea.

## Evidence boundaries

No live model/API experiment was run in this review. The reported 403 remains a blocker for validating model-dependent improvements; no credentials or blocked endpoint were accessed. Literature scores cannot be substituted for CMP results. Keep a frozen holdout, disclose model/version and construction cost, cluster uncertainty by conversation/task family, and distinguish successful retrieval from successful use. The current 40-case synthetic result is a useful diagnostic, not a production reliability estimate or evidence of frontier performance.
